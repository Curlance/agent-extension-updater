# 自动更新开关（可选模式）

默认关闭。打开后，只执行已授权范围内、通过下述全部检查的独立 Git 扩展更新。版本号不能证明行为兼容性；这里不承诺自动判断所有破坏性变更。Agent 本体永远不在范围内。

## 开关与存储

配置位置：`$AGENT_EXTENSION_UPDATER_CONFIG`，默认 `~/.agent-extension-updater/config.json`。
备份、日志和锁文件存放在配置文件的同一父目录。自定义配置路径会同时隔离这些状态文件。

```json
{
  "schema_version": 1,
  "auto_update": {
    "enabled": false,
    "scope": {
      "hosts": ["dsh", "hermes", "codex", "claude"],
      "kinds": ["技能", "插件"],
      "exclude": []
    }
  }
}
```

- `enabled` 必须是布尔值；不存在的配置视为关闭，损坏的配置报错而不静默回退。
- `scope.hosts` 指定允许的宿主；缺省或空数组表示所有已识别宿主。共享技能目录需要其所有已识别使用宿主都在范围内。
- `scope.kinds` 只允许技能和插件；`scope.exclude` 按名称排除。
- 开关授权持续到 `--disable`，不等于启用定时器。

## 执行条件

核心检查实现在 `scripts/lib.mjs`，不受配置覆盖：

1. 只处理技能和插件，且盘点状态为 `有更新`。
2. 必须有可固定目标的 Git 动作；需要先退出宿主的更新只登记待手动。Hub、宿主管理的插件和未适配协议不自动执行。
3. 当前版本必须能从技能或包元数据读取；远端目标提交必须有唯一语义版本标签。未知版本、主版本变化、降级和预发布目标均跳过。
4. 仓库根必须等于扩展目录；共享大仓库子目录、worktree、符号链接和 junction 不自动执行。工作区必须干净。
5. 任一条目或目录扫描检查失败，停止整轮更新，返回非零退出码。未适配、无来源与检查失败分别报告。
6. 实际更新前完整备份文件并校验哈希。备份失败、内容变化或审计无法写入时，不执行更新。
7. 使用实际跟踪的远端和分支，固定检查时的提交。获取提交后再次核对目标、原 HEAD、分支、远端地址、工作区及祖先关系；任一变化都停止。读取目标内容的版本与标签比对通过后才快进更新。
8. 更新后按精确路径读回提交、版本及技能名称，全部通过才记录 `已落盘待重载`。验证失败不会保留成功记录。任一执行失败即停止本轮剩余项目。

同一配置目录通过 `run.lock` 排他执行；另一个运行存在时不抢锁。进程异常退出可能留下锁，应先确认原进程已结束再由用户清理。不同配置目录之间没有全局锁。

## 命令

```bash
node scripts/auto-update.mjs --status
node scripts/auto-update.mjs --enable --hosts dsh,codex
node scripts/auto-update.mjs --disable
node scripts/auto-update.mjs --run --dry-run --project <项目目录>
node scripts/auto-update.mjs --run --project <项目目录>
node scripts/auto-update.mjs --report --lines 20
node scripts/auto-update.mjs --restore <record.json> --to <新目录>
```

`--hosts` 只用于保存启用范围，实际运行从配置读取范围。`--dry-run` 在关闭状态下也可使用，会查询上游，但不写扩展、备份、锁或本工具的审计日志。npm 查询可能更新其自身缓存。检查或执行失败以非零退出码退出，便于调度器发现失败。

## 备份与恢复

每项在 `<配置父目录>/backups/<时间与随机标识>/<路径身份>/` 保存：

- `files/`：完整技能或插件目录，包含独立 Git 仓库的 `.git`。
- `record.json`：原路径、名称、宿主、原提交、目标提交及每个文件的 SHA-256 清单。

复制前后校验源目录和备份，防止静默漏文件或复制期间源文件变化。同名不同路径有不同身份，记录不会互相覆盖。链接或特殊文件不自动备份。备份可能包含本地 Git 配置，应仅留在受保护的本机目录。

恢复命令先核对哈希，然后复制到**尚不存在的新目录**并再次校验；不会删除或覆盖当前安装。确认恢复内容后，再通过宿主认可的方式接回安装目录。备份无法撤销全局依赖变更、外部配置或宿主运行中的状态。

## 审计与验证

`auto-update.log.jsonl` 每行是一条 JSON。事件包括 `enable`、`disable`、`update-start`、`update` 和 `run`。单项最终记录携带路径身份、原提交、目标提交、备份位置、最终状态和错误；只有验证通过的 `update` 事件才会有 `ok: true`。

成功只表示文件到达目标提交和版本，**不表示宿主已加载或扩展行为兼容**。宿主重启、重载和运行时验收仍需按各宿主规则进行。

## 调度

本技能不会常驻或自行创建定时任务。宿主调度器或系统计划任务可以调用以上命令；默认只做检查，实际执行依赖已保存的开关和每轮重新检查。

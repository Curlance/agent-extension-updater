# 设计说明

## 范围

**管理 Agent 的 skills 与 plugins 的版本**：盘点、确认、备份、更新、验证。

明确不在范围内：

| 不管理 | 原因 |
| --- | --- |
| **Agent 本体** | 升级会中断运行时会话、可能影响共享 profile；各宿主渠道差异极大（源码 / MSIX / Store / 桌面 / IDE）。只登记为"随本体、跳过"。 |
| MCP 服务 | 独立生命周期，不随技能/插件分发。 |
| 模型、操作系统、无关软件 | 与扩展维护无关。 |

## 支持矩阵

| 宿主 | 技能来源 | 插件来源 | 触发自动化的方式 |
| --- | --- | --- | --- |
| DeepSeek Harness | `<项目>/.dsh/skills`(100)、`<项目>/.agents/skills`(200)、`$DSH_HOME/skills`(400)、`~/.agents/skills`(500)、随包(600) | profile 的 `dependencies` + `dsh.profile.bundles` | 宿主会话内调度，或系统计划任务调脚本 |
| Hermes | `$HERMES_HOME/skills/<分类>/`（hub / bundled / local） | `$HERMES_HOME/plugins` | `hermes cron create … --skill` |
| Codex | `~/.agents/skills`、`.agents/skills` | `~/.codex/plugins` | 系统计划任务 |
| Claude Code | `~/.claude/skills`、`.claude/skills` | 插件管理器 | 系统计划任务 |
| 通用 | 按宿主文档 | 按宿主文档 | 能力分级：仅网页 / 可读文件 / 可执行命令 / 可调度 |

## 工作流

```
① 识别宿主（模型名不是客户端名）
② 只读盘点 → 清单：名称 / 真实路径 / 渠道 / 来源 / 当前→目标 / 变更与兼容性 / 重启影响
③ 主动确认（绑定具体项目 + 来源 + 目标版本）
④ 备份 → 用宿主官方渠道逐项更新 → 记录退出码
⑤ 验证 → 报告：已验证生效 / 已落盘待重启 / 失败 / 跳过 / 检查失败 / 恢复状态
```

检查阶段严格只读：不安装、不升级、不启用、不修依赖、不重启、不改更新源。

## 状态词表

| 状态 | 含义 |
| --- | --- |
| 有更新 | 已确认可信上游且目标版本明确 |
| 已最新 | **已取得上游版本并比较通过** |
| 检查失败 | 网络、权限、命令缺失等导致无法判断——**不是"已最新"** |
| 无来源 | 找不到可信上游（本地自定义属于此类，跳过） |
| 待适配 | 接口未核实，需要现场查 `--help` 或官方文档 |

## 判定规则（脚本与文档同源）

1. **读不到本机版本时记"检查失败"**，绝不因为远端有版本号就报"有更新"。
2. **Git 项只读比较远端提交**（`git ls-remote`，不写本地 refs），不用字符串排序比较版本。
3. **解析真实路径后去重**；跨授权目录的符号链接 / junction 先停下确认。
4. **不得对"单个 skill 所在的大仓库"直接 `git pull`**；当前脚本将共享仓库子目录列为待人工处理，隔离 staging 更新尚未实现。
5. Git 检查绑定当前 upstream 的远端、分支和提交，执行获取后检查目标不变、工作区干净且允许快进；读取目标内容版本，防止标签与内容不一致。
6. 技能与插件均完整备份并验证文件哈希。复核精确路径的提交和版本后才记录成功；单项失败停止本轮后续更新。

## 自动更新开关

默认关闭。开关文件在 `~/.agent-extension-updater/config.json`（不在仓库内）。自定义配置路径同时隔离备份、审计与锁文件。损坏配置报错，不能当作默认配置覆盖。

**核心护栏位于 `scripts/lib.mjs`，由 `scripts/auto-update.mjs` 调用，配置文件改不动：**

| # | 护栏 | 行为 |
| --- | --- | --- |
| 1 | 本体永不涉及 | `kind` 为"本体"一律拒绝，配置误写也不行 |
| 2 | 只动有明确动作的项 | 状态必须是`有更新`且带结构化 `updateAction` |
| 3 | 需先退出宿主的不动 | `requiresAppQuit`（如 DSH 插件）→ 登记"待手动" |
| 4 | 版本不确定不动 | 主版本变化、版本未知、降级和预发布目标均登记"需确认" |

另外：**任何条目或扫描检查失败，整轮不做更新**。状态和退出码均反映失败，不会输出"没有需要更新"。无法确认协议的项仍报告待适配，不冒充检查成功。

## 脚本职责

| 脚本 | 职责 | 写盘 | 联网 |
| --- | --- | --- | --- |
| `inventory.mjs` | 只读盘点，输出文本或 JSON | 不改扩展；npm 可能写自身缓存 | 仅 `--check-updates` |
| `auto-update.mjs` | 读开关、套护栏、备份、执行、审计 | 实际执行写备份、日志、锁与扩展；演练不写本工具状态 | 实际运行和演练均查询上游 |
| `lib.mjs` | 语义版本、Git 固定目标、备份校验和恢复 | 由调用操作决定 | Git 检查及获取时 |
| `check-skill.mjs` | 技能自身结构自检 | 否 | 否 |

## 已知限制

- **DSH 的 npm 插件无法在运行中的会话里自动更新**（`dsh plugin` 要求先完全退出桌面端），这类项只会被登记为"待手动"。目前可自动的只有 Git `link:` 类插件。
- **文件落盘 ≠ 已生效**：多数宿主需要重启或新会话才加载新版本。
- **Codex / Claude Code 的插件更新接口未在真实环境核实**，只做盘点与能力检测。
- 技能**不是常驻程序**，不自行定时运行；定时检查由宿主调度能力接入。
- 宿主迭代较快（DSH 本机为 0.2.0-rc.2），执行前应先用 `--help` 复核接口。
- 当前自动执行范围仅独立 Git 技能及 DSH 本地插件；目标需唯一版本标签，版本号不能证明运行时兼容。
- 恢复只复制到新目录，不自动替换当前安装。锁仅协调同一配置目录的更新进程。

## 回归测试

`node --test tests/updater.test.mjs` 使用临时目录与本地 Git 仓库，覆盖完整更新及备份恢复、非 main 分支、远端变化、分叉、本地修改、版本未知、同名扩展、备份与验证失败、部分盘点失败、锁和审计故障。无需网络或真实宿主安装。CI 覆盖 Windows/Linux 和 Node 18/22。
